# DG900 Pro 编程补充记录

本文件记录项目中的实机验证，供配合 [DG900 Pro 编程手册](../manuals/DG900Pro_ProgrammingGuide_CN0.pdf) 使用；不属于厂商原文。

## 高阻负载设置实测（2026-10-10）

测试日期为北京时间 2026-10-10。设备为光功率信号源，型号 **DG912 Pro**，序列号 **DG9Q280100002**，固件版本 **00.02.01.00.02**。

`*IDN?` 实机返回：

```text
RIGOL TECHNOLOGIES,DG912 Pro,DG9Q280100002,00.02.01.00.02
```

### 命令与回读

本次将 CH2 设置为高阻，使用以下 SCPI：

```scpi
:OUTPut2:LOAD INF
*OPC?
:OUTPut2:LOAD?
```

PyVISA 中，设置命令使用 `write()`；`*OPC?` 和负载回读使用 `query()`。CH1 的对应设置命令为 `:OUTPut1:LOAD INF`。

在这台设备及固件上，高阻负载回读为 `9.9E+37`。数字负载 `1` 表示 **1 Ω**，`50` 表示 **50 Ω**，均不能作为高阻设置。驱动对高阻数值回读以 `>= 9e37` 验证。

### CH2 设置前后记录

| 记录项 | 设置前 | 设置后 |
|---|---|---|
| CH2 负载回读 | `+1.000000000000000E+00`（1 Ω） | `9.9E+37`（高阻） |
| CH2 偏置回读 | `0.0019608 V` | `0.1 V` |
| CH2 幅度回读 | `0.0019608 V` | `0.1 V` |
| CH2 输出状态 | ON | ON |
| CH1 负载回读 | `9.9E+37`（高阻） | `9.9E+37`（高阻） |

此前对 CH1 也执行过 `:OUTPut1:LOAD INF`，设置前后均回读为高阻。CH2 测试使用独立连接，并指定 `apply_load_policy=False` 跳过连接时的自动负载策略，只写入 CH2 负载；未发送幅度、偏置、输出开关或参考时钟设置命令。

### 结论与未确认事项

- **已验证**：`INF` 能在上述 DG912 Pro 及固件上设置高阻；CH2 从 1 Ω 回读变为高阻，CH1 保持高阻。
- **读数变化**：仅修改负载后，CH2 的幅度和偏置回读同时变化。负载设置会影响仪器的电压数值解释，应在更改负载后重新核对幅度和偏置。本次未用示波器或万用表测量端口电压，不能据此断言实际电压发生了相同比例的变化。
- **1 Ω 成因尚未证实**：此前代码写入的是 `INFinity`，没有把数字 `1` 当作高阻发送。本次未重新测试该长参数，不能把它认定为负载变成 1 Ω 的已确认原因。
- **参考时钟另行验证**：本次未测试时钟同步。用户此前观察到设备提示没有有效外部时钟源并退回内部时钟；瞬时回读为外部时钟源不能证明随后持续锁定成功。

### 项目中的处理

DG900 驱动的高阻参数现统一发送 `INF`，设置后回读验证，目标与回读不符即报错。参考时钟批量同步入口沿用工厂默认负载策略，连接时先设置两路负载，再设置参考时钟；加热信号与温度开关信号的目标均为高阻。上面的实机测试仍通过 `apply_load_policy=False` 隔离自动负载设置，未测试温控设备或批量同步流程。相关接口及负载策略见 [信号发生器模块说明](signal_generator.md)。

## GUI 高阻回读再次应用的问题（2026-10-10）

用户在 Pump 光功率面板点击“应用并回读”时，负载框显示 `9.9E+37`，报错为“期望 9.9e+37 Ω，实际 1 Ω”。代码核对确认：界面将高阻数值回读原样提交，后端将它转换成普通数值阻抗，驱动缺少数值高阻标记的识别，因而发送数值负载而非 `INF`。

修正后，GUI 将高阻回读显示并提交为 `INF`；两款信号源驱动共用负载归一化，将 `>= 9e37` 的数值或数值字符串识别为高阻，DG900 写入 `INF`，DG4000 写入 `INFinity`。这也兼容旧页面已缓存的数值回读。`get_output_load()` 保留原始查询字符串，普通 1 Ω、50 Ω 负载不转换成高阻，DG900 继续回读验证。

本次修复通过假仪器和前端模拟请求验证，未新增实机操作或端口电压测量。
